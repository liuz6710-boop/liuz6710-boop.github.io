— THE PROBLEM

Robots fail quietly. Engineers shouldn't have to.

Mobile robotics teams debug behavior across sensor streams, path plans, and physical environments. When a robot stops, slows, or takes the wrong route, the engineer's first task is rebuilding what the robot saw — usually from raw logs and a memory of the warehouse layout.

The team needed a single pane of glass: a live view of the fleet, the 2D paths each robot was driving, and the 3D point cloud each robot perceived. Plus a faster way to build the dozens of small internal UIs the team needed for everyday tool-making.

— MY ROLE

Listen first. Build the right thing second.

I started with user research — sitting with robotics engineers, watching them debug, asking what slowed them down. From there:

  • Designed a real-time data monitoring dashboard with 2D fleet visualization (positions, paths, statuses) layered against a live 3D point-cloud view.
  • Developed a Web UI generation toolset that converts design mockups into reusable frontend components, auto-wiring them to pre-built backend services for rapid prototyping.
  • Applied rule-based automation and AI-assisted workflows to streamline component generation — significantly reducing manual frontend effort for the team's everyday tooling.

— APPROACH

Two layers, one window.

2D fleet layer

Real-time robot positions on the warehouse map, with path overlays and status badges. The first thing an engineer wants to see when something looks off.

3D point cloud

Live point cloud rendering for the robot's perceived environment — letting engineers see what the robot sees, not just what we hoped it would see.

Mockup → component

Designers hand off Figma; the toolset emits reusable React components, wired into the team's existing backend services with sensible defaults.

Rule + AI assist

Rule-based generation handles the boring 80%. AI-assisted prompts handle the variable rest. Engineers ship internal tools in hours instead of days.

— OUTCOMES

What I left behind.

  • Observability for the fleet — engineers stopped reconstructing robot state from logs; they watched it live.
  • Faster internal UI delivery — the generation toolset converted mockups directly into working components, removing the slowest step of internal tooling.
  • Rule + AI hybrid workflow — a template for future internal tools to standardize the boilerplate and accelerate the rest.
  • User research as default — observed-engineer-debugging became the default discovery method for the team's tooling work.
